Harness, model and provider choice

Choose the tools for each role

The adapter path starts with Claude Code, followed by planned Codex and Pi adapters. The choice has three parts, while the delivery gates stay the same.

  • Harness

    The coding-agent program that runs a role’s work: Claude Code first, with Codex and Pi to follow. Each adapter must fit the same pass contract and sandbox boundary.

  • Model

    The model doing the implementation or review. Configure it per role: an author using Claude could have a reviewer using an open-weight model through the planned Pi adapter.

  • Provider

    The service or endpoint serving that model. Pi’s multi-provider support is the planned path to hosted providers, self-hosted models and supported custom endpoints.

Mixed-role configurations are candidates to evaluate, not proven quality improvements. Supported combinations depend on the harness, adapter, provider and sign-in path; they need not perform equally.

What you get

Hand over the work, keep the judgement

  • No agent approves its own work

    The author and the reviewer are separate GitHub identities with separate keys and sandboxes. Neither can act as the other.

  • A review that can block the merge

    The review is a required check on the exact commit. A new push clears it, and GitHub will not merge without it.

  • You decide what merges

    You choose which changes need your approval, and changes to the rules Forgecrew enforces always do. When a task cannot be done as written, the agent can say so instead of faking it.

  • Keep infrastructure in your control

    Open source and self-hosted, with nothing exposed to the internet for incoming work. Provider credentials and forge role credentials have separate purposes; choosing a provider does not change a role’s authority.

For teams

Free core. Planned enterprise capabilities.

  • Safety gates in the free core

    The Apache-2.0 core stays free, including separate role identities, sandbox isolation and exact-commit review and merge gates.

  • Operate across an organization

    Paid enterprise capabilities are planned for organization administration, audit and reporting, policy deployment and support. These capabilities have not shipped.

  • Shape a pilot around your workflow

    Bring your repositories, approval rules and deployment requirements. Open a pilot discussion to help define what your team needs.

FAQ

Questions

What does Forgecrew add to a coding harness?

The delivery workflow around each agent: role identities, sandboxes, review gates and the rules that decide when work can proceed. The harness does the coding or reviewing; Forgecrew’s design keeps its authority within the role and checks the required verdicts before merge.

What does it cost?

The core is free under Apache-2.0. Model usage and the machine it runs on are separate costs. The technical design covers supported subscription and API sign-in paths; enterprise capabilities are planned as paid additions.

Can the author and reviewer use different models?

That is part of the planned configuration per role. A different model does not itself make a review independent: the reviewer also needs its own forge identity, credential boundary and sandbox. Model pairings need evaluation on your work; no pairing has been established as best.

What if someone writes instructions into an issue?

Forgecrew limits what a misled agent can do rather than promising it cannot be misled. Only people you allow can start work, and pull requests from forks are never picked up automatically. An agent holds no GitHub credential and reaches no network but its model provider, and everything it wants to post passes rules that reject, for example, text containing a secret.

What is not solved yet?

The sandbox experiment in #15 ran Claude Code headless with its network limited to the model API and its token kept out of every command line and file. One leak is open: a program the agent starts can read the token from the agent’s environment. The planned fix adds the credential at the network boundary instead (#7). Until then, Forgecrew treats anything the agent runs as able to read that token.
