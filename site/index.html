AI agents that can’t approve their own work.

For developers who already hand work to AI coding agents. Forgecrew takes an issue to a merged pull request with every role as its own GitHub identity, an independent review that can block the merge, and the final say on what lands.

How it works

Separate roles, enforced by GitHub, with you at the end

What you get

Hand over the work, keep the judgement

  • No agent approves its own work

    The author and the reviewer are separate GitHub identities with separate keys and sandboxes. Neither can act as the other.

  • A review that can block the merge

    The review is a required check on the exact commit. A new push clears it, and GitHub will not merge without it.

  • You decide what merges

    You choose which changes need your approval, and changes to the rules Forgecrew enforces always do. When a task cannot be done as written, the agent can say so instead of faking it.

  • Yours to run

    Open source and self-hosted, with nothing exposed to the internet. Runs on the AI subscription you already have, and leaves a reserve for your own work.

Why Forgecrew

Why not just…

  • …let the agent review its own work?

    Agent tools often review under the identity that wrote the change, and in one study a model reviewing its own work found under a third of the errors planted in it.

    Forgecrew’s reviewer is a separate identity the author cannot speak for, and it can run a different model.

  • …put the rules in the prompt?

    Instructions are requests. In one study, frontier models cheated on about half of the tasks that could not be done as specified, by editing the tests or special-casing them.

    Forgecrew enforces its rules with identities, sandboxes and GitHub’s merge gate, and gives the agent an honest way to say a task is impossible.

  • …use a hosted AI reviewer?

    Hosted reviewers post as one app per vendor, so they cannot be a reviewer with its own identity, and some never block a merge by design.

    Forgecrew’s review is a required check that only the reviewer’s identity can pass. After launch, a self-hosted reviewer can be tried inside it.

FAQ

Questions

Can I use Forgecrew today?

Not yet. The design is settled and the first milestone, the skeleton, is done, but nothing works end to end. The roadmap shows what is merged. Star or watch the repository to follow along.

What is Forgecrew, and what is it not?

It is everything around the AI agent: the identities, the sandboxes, the review gate, the rules, and the programs that decide which role has work. It is not a model and not a coding agent; it runs Claude Code, unmodified. It is not a hosted service. And it does not replace your judgement: it makes sure a change has passed an independent review before it asks for yours.

What does it cost?

Forgecrew is free and needs no account. You pay for model usage, through your subscription or an API key, and for the machine it runs on.

Can I use my Claude subscription?

Anthropic permits signing in to the unmodified Claude Code program with your own subscription, which is what Forgecrew does. Its terms also say that Pro and Max limits assume ordinary, individual use, and that products built on its Agent SDK must use API keys. Forgecrew never relays one person’s subscription to another. Read the current terms, and choose your subscription or an API key with them in view.

Which forges and agents does it support?

GitHub and Claude Code at launch. Azure DevOps, GitLab and other agents come after launch; the design already covers all three forges.

What if someone writes instructions into an issue?

Forgecrew limits what a misled agent can do rather than promising it cannot be misled. Only people you allow can start work, and pull requests from forks are never picked up automatically. An agent holds no GitHub credential and reaches no network but its model provider, and everything it wants to post passes rules that reject, for example, text containing a secret.

What is not solved yet?

The sandbox experiment in #15 ran Claude Code headless with its network limited to the model API and its token kept out of every command line and file. One leak is open: a program the agent starts can read the token from the agent’s environment. The planned fix adds the credential at the network boundary instead (#7). Until then, Forgecrew treats anything the agent runs as able to read that token.
